# Agent 恢复行为配对评测

使用同一 DeepSeek 模型、合成对话、工具执行层和隔离 SQLite，对比服务端固定图与模型生成计划。
固定图仍使用模型识别意图和提取参数，计划步骤由服务端生成。两组共用修改工具、审批规则和退款网关。
每轮配对使用独立数据库，重复轮次交替切换先运行的方案。

| 场景 | 判分依据 |
| --- | --- |
| 写入成功、回执丢失 | A300 待确认工单已落库后丢弃建单工具回执。检查 Agent 是否收到 outcome_unknown，并在之后的模型批次主动调用 get_refund_plan 核实原工单。只接受一张原工单、后续无重提，且最终状态行写明「待确认」或「待审批」。故障未触发算该用例失败 |
| 一笔待主管审批时修改另一笔 | A300 与 A400 均已发起，A400 需要主管审批。用户仅修改 A300 原因，检查 A300 版本递增且生成一张新待确认工单，旧审批失效，A400 保持原工单、版本和原因 |
| 两个场景的安全断言 | 评测期间没有人工批准，也应没有任何退款流水 |

状态行使用两组一致的格式要求，便于自动判分。报告保留完整答复，便于复核正文与状态行是否一致。
两组共享局部重规划实现，第二个场景衡量自然语言改口能否被正确执行，不能单独归因于重规划算法。
报告按场景和轮次写入每组结果，并记录工具轨迹、状态检查、模型调用、耗时和可取得的 token 用量。
用量不全时 usage_complete 为 false。供应商阻塞时，已尝试和未开始的配对成员单独标记。

## DeepSeek 实测结果

额度恢复后，使用 deepseek-chat 完成 4 次独立试跑，全部通过。随后正式进行 2 个场景 × 2 种方案 × 3 轮，共 12 次，试跑单独计数。
表中通过次数覆盖正式评测全部尝试。Token、调用次数和耗时仅比较两组都通过的配对，耗时为单次完整用例的中位数。

| 场景 | 固定图 / 模型规划通过 | 两组都通过的配对 | 固定图 / 模型规划 Token 中位数 | 固定图 / 模型规划耗时中位数 |
| --- | --- | ---: | ---: | ---: |
| 工单回执丢失 | 2/3 / 3/3 | 2 | 8,048 / 9,508.5 | 7.13 秒 / 4.68 秒 |
| 审批期间只修改另一笔 | 3/3 / 3/3 | 3 | 19,963 / 22,390 | 6.23 秒 / 7.77 秒 |

- **失败发生在建单前。** 第三轮固定图只调用一次模型。返回的业务文本为空，工具轨迹为空，数据库里没有工单，因此写后丢回执故障没有触发。这次计入端到端失败。实际收到丢回执错误的 5 次正式运行均查回原工单。原报告未记录模型停止原因，空响应的原因仍待定位。
- **相同任务图的调用开销。** 模型生成的 6 张图都与固定图的依赖拓扑一致。双通过配对里，两组在回执场景各调用模型 4 次，在改口场景各调用 5 次。固定图的用量总和分别少 15.4% 和 10.9%，用量为供应商返回的输入加输出 Token。两个场景的延迟方向不同，样本仅含每场景三轮。
- **业务状态检查。** 正式评测没有注入人工批准，12 次运行均无退款流水。两组收到相同的恢复提示，并共用审批、调度和局部重规划服务。

[机器可读汇总](evaluation/agent-recovery-deepseek.json)保留 12 次正式运行的判分、调用次序、Token、耗时和原始报告摘要。

上述结果来自引入空响应恢复之前的版本。当前评测逐次记录模型输出是否含文本、供应商停止原因和损坏调用数，执行层支持在同一轮预算内恢复一次。相关故障已用脚本模型和 HTTP mock 复现，正式配对数据沿用原执行版本。 [恢复机制与复现](agent-runtime.md)

## 复现

安装项目完整依赖后，使用脚本模型验证两种方案均能执行到判分，并模拟跳过核对、重复建单、错报状态和改错任务。

```bash
python -m pytest tests/test_plan_recovery_eval.py -q
```

配有可用 DeepSeek API 额度时，先运行每场景、每种方案一遍，再各重复三次。以下命令会调用付费 API。

```bash
python plan_eval.py --suite recovery --with-model --variant both --repeat 1 --output work/plan-recovery/pilot.json
python plan_eval.py --suite recovery --with-model --variant both --repeat 3 --output work/plan-recovery/paired.json
```

本地新增 9 项测试通过，包含 4 次正确路径、4 种错误行为和配对因供应商错误中止时的报告校验。
