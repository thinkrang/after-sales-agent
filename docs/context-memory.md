# Loop 边界、上下文压缩与长期记忆

## 循环边界

`agent_context.ContextBoundary` 是生产对话 Agent 的中间件，不只用于评测。
`Limits` 集中配置默认边界：每轮最多 10 次主模型调用、16 个工具调用位置、
同名同参数工具最多 2 次；每轮 120 秒，在发起下一次模型/工具调用前检查。
API 另外设置 40 步递归兜底。正在进行的请求不会被强行中断，仍受模型请求自身超时限制；
因此 120 秒是协作式停止点，不是严格的 HTTP 总耗时上限。证据核查等工具内部调用不单独计入主模型次数。

计数来自最新一条用户消息之后的真实图消息，下一轮自动重置，不使用进程级全局计数。
工具预算按整个批次的位置检查，避免模型一次发出多个并行工具调用绕过边界。
重复调用按工具名与排序后的 JSON 参数识别；参数不同的无效循环由总次数上限兜底。

被拦截的工具仍返回对应 call id 的错误 ToolMessage；随后模型节点直接生成中文停止说明，
不再请求远程模型，保留工具调用与结果配对。停止原因会出现在 SSE 与历史记录中，
下一条用户消息可以正常继续。已经完成的动作以数据库工单为准，不声称停止等于退款撤销。

## 请求时压缩

模型请求中的消息与系统提示合计预算默认为 24,000 字符，**不是精确 tokenizer token 计费上限**，
也不包含工具 schema。默认保留最近 3 个完整用户轮次；预算紧张时收缩到当前完整轮次。
旧对话只保留最近若干用户/助手片段，形成最多 2,000 字符的确定性摘录，不调用额外摘要模型。

- 不改写或删除 checkpoint 中的原始消息，页面与历史接口仍可追溯。
- 按完整用户轮次裁剪，核对旧区间的 tool call/result 配对，不拆散工具交互。
- 旧摘要标注为不完整背景，不作为新用户请求或授权。
- 每次模型调用重新从服务端加载当前任务版本、订单、原因、工单状态和用户偏好。
- 当前轮次自身过大时明确停止并要求分步处理，不静默截断它的工具结果。

这是一种有损的抽取式压缩，不是无损语义总结。没有进入任务表的旧细节可能被省略，
需要时应重新查原始业务工具或向用户确认。审批、金额和资格始终以业务服务为准。
原始 checkpoint 的存储增长和清理策略是另一项运维问题，本实现不把请求压缩当作数据库清理。

## 长期记忆

### 用户偏好

`long_memory.py` 将偏好存入按 tenant + user + key 隔离的 SQLite 表，跨会话/重启可读取。
只接受封闭的类型和值：

| key | value |
|---|---|
| language | zh-CN / en |
| response_style | concise / detailed |
| contact_channel | chat / email |

偏好只供表达参考，不能覆盖应用系统指令（例如当前客服的中文要求）、政策或审批。
模型写入工具要求当前真实用户消息以“记住/请记住/帮我记住/请帮我记住”开头，
包含对应偏好词且无否定词；不接受检索文档中的记忆请求。该门槛有意保守，
不支持的表达应让用户明确重述，或直接使用管理 API。
默认 90 天过期，管理 API 可设置 1–365 天；读取时过滤并清理过期记录。
同一 key 的明确新偏好覆盖旧值。只保存偏好枚举、时间和来源轮次 id，不保存整段原始指令。

管理接口（均来自当前 token 的用户/租户，不接受自报归属）：

```text
GET    /memories
POST   /memories       {"key":"response_style","value":"concise","ttl_days":90}
DELETE /memories/response_style
```

聊天示例：“请记住我喜欢简洁回答”“忘记我的回答风格偏好”。
删除长期偏好不会删除原有聊天原文、订单或财务审计记录，也不是全账户数据删除。

### 售后经历

`recall_after_sales_history` 只读查询当前用户最近 3 条已结束售后记录，最多支持查询 5 条。
返回来源工单 id、订单、状态、金额、退款单号和时间，不从模型摘要生成“曾经成功退款”的事实。
不同用户及租户隔离；历史退款不能授权新退款。业务记录的保留期限独立于偏好 TTL。

## 验证

`tests/test_context_memory.py` 覆盖重复调用、并行批次预算、模型/时间/上下文边界、
SSE 停止说明、下一轮恢复、工具消息配对、压缩后保留完整 checkpoint、重新加载待审批任务、
偏好隔离/过期/删除、明确写入门槛、跨会话注入和来源可追溯的售后经历。
所有金额操作继续经过原审批/幂等链路。真实模型冒烟与历史对照结果分开记录，
不将本轮功能测试解释为生产准确率或 token 成本提升。

本轮验证：完整回归 234 项通过、1 项跳过、2 项真实模型 pytest 用例按标记排除。
另外实际调用 deepseek-chat 完成补槽、待审批插话、取消 3/3 任务，以及偏好保存、
跨会话回忆和明确忘记链路。小规模冒烟结果见 [验证摘要](evaluation/context-memory-smoke.json)。
