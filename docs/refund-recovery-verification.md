# 退款恢复与重规划验收

## 会话关闭与回执

删除会话时，工单库在同一事务里检查活动工单和写入关闭标记。有待确认、待审批、已批准或执行中的工单时，API 返回 409。
调度器已领取的旧任务也必须通过工单库的关闭检查才能建单。定时清理使用同一保护条件。

聊天记录从终态工单生成回执。正常审批、后台计划恢复和对账完成的退款由同一个接口展示。
退款成功不再需要一次独立的 checkpoint 回执写入。旧版已写入 checkpoint 的回执按工单 ID 去重。

HTTP 集成测试在批准落库后、模拟网关成功后、工单终态落库后三处模拟中断。每个场景连续恢复两次，
检查退款流水一条、聊天回执一条，并确认另一笔工单仍待审批。另覆盖关闭会话与已领取建单步骤交错执行。

## 知识库引用校验

核查器输出本次召回的片段编号和连续原文。服务端校验片段范围以及原文是否匹配，并取回该片段的文件名和页码。
Web 与 MCP 只把通过校验的引用交给回答端。定向测试覆盖引用编造、数字改写、串错来源、引用不存在的片段和 PDF 换行。
当前核查契约使用一段连续证据。含例外、冲突规则或跨文档结论时，仍需用真实模型评测答案是否完整、适用。
同一轮检索留出题中，混合召回 R@3 为 10/11，纯向量为 11/11。

## 复现

```bash
# 双订单演示，使用轻量依赖
python -m pip install "fastapi==0.147.0" "pydantic==2.13.5" "python-dotenv==1.2.3"
python -m evaluation.plan_eval --cases dual --output work/planning/demo.json

# SQLite 终态与重规划步数
python -m evaluation.plan_eval --repeat 3 --output work/planning/system.json
python scripts/compare_replanning.py --repeat 10 --output work/planning/replanning.json

# 完整隔离验收
python scripts/verify_project.py --output work/verification

# 真实模型配对试跑，会使用 API 额度
python -m evaluation.plan_eval --with-model --variant both --cases dual --output work/planning/model-pilot.json
```

已用没有 `.env` 的临时源码目录和只安装上述轻量依赖的新 Python 虚拟环境运行双订单演示，
确认 A300 和 A400 各产生一笔模拟退款。

评测使用模拟订单和支付网关。模型配对场景使用合成对话，报告记录工单终态、退款流水、模型调用、可用的 token 用量和供应商故障。
