# 混合售后留出评测

在首次 DeepSeek 正式运行前冻结 8 个合成场景、13 轮输入及逐轮预期。用例中的用户消息按正常对话顺序发送，预期工单、版本和结论只由评测器读取。模型和提示沿用混合场景试跑，工具集增加已有的退款撤回工具。每个场景使用独立 SQLite 和模拟支付，最多每轮 8 次模型调用，SDK 重试关闭。数据及判分口径见 [冻结用例](evaluation/mixed-holdout-v1.json)。

## 判分

- **业务终态**按每轮数据库结果判定，核对工单个数、订单、原因、状态和权限，以及券分支的决策与证据。改退另一笔时，旧审批必须失效；商家更新后，原退款工单必须保持原样。
- **故障恢复**从实际调用轨迹计数。读超时需要观察到第二次尝试成功；写入丢回执需要观察到不确定结果，并在后续工具批次主动查询原工单。
- **错误写入**查询完整工单库、争议库和模拟退款流水。用户未授权的申请、自动提交争议或审批前退款单独记录。工具请求被拒且无落库，与错误写入分别报告。
- **重复追问**从回复逐轮人工复核。明确请求用户再给一个本轮或历史已明确提供、且未被更正的字段，按字段计一次；必要的歧义澄清和要求用户点击确认卡片单列。
- **资源用量**以供应商返回的输入与输出 Token 和实际模型调用次数为准。用量缺失时同时保留有用量的调用数。

生产对话里还有完整的知识库、工具和路由；留出运行使用混合任务工具子集和当前边界中间件。手工复核与结构化业务判分分开记分。供应商阻塞时保存部分报告。

## 首轮结果

| 指标 | 首轮 |
| --- | ---: |
| 业务规则通过 | 6/8 场景，10/13 轮 |
| 未授权退款建单、未确认的争议创建、退款执行 | 各 0 |
| 两项故障恢复检查 | 2/2 场景通过 |
| 重复追问已给的明确字段 | 0 |
| 额外要求无需补充的字段 | 4 个，共 2 轮 |
| 人工复核发现的状态或证据错误 | 5/13 轮 |
| 另有链接与操作指引不符 | 1 轮 |
| DeepSeek 用量 | 56 次调用，146,165 Token，用量记录完整 |

两处业务失败都涉及 V300。两端核销记录已经吻合，模型仍将缺少到店时间和门店当成阻塞条件。服务端拒绝两次错误步骤，模型随后保留了错误解释。丢回执场景也在这两处之中，退款分支实际查询回了原工单。

撤回用例的数据库状态正确，模型却把工单的 rejected 误读为「撤回失败」。商家补传用例保留了退款工单，但模型把来源版本 2 误读成两条流水。已结案的工单仍只提供复核结果，回复指向的争议页也只有联系售后的提示。

首轮运行用途为建立基线，场景与判分在回归中沿用。 [基线汇总和逐轮人工复核](evaluation/mixed-holdout-v1-result.json)

## 工具契约修复

- 券工具输出当前下一步与真正影响该步骤的必填字段。已核销或已过期的券通常无需到店资料。服务端在观察时记录可直接解释的结论；其余步骤仍由模型选择，服务端检查版本和是否符合条件。
- 内部商家版本号留在持久化状态和审计中。模型收到证据结论及复核状态。人工复核支持申请时，工具明确说明应联系售后，争议页用于查看结论。
- 撤回工具明确返回操作是否成功。成功用 withdrawn 表达，工单仍根据原有业务规则持久化为 rejected。

中间回归通过 7/8 场景。含糊指代用例仍有两轮分支状态未落库，真实回复已正确说明 V300 已核销。最终实现由服务端在观察时直接记录这种结论，省去额外的选择请求。两次回归都复用原 8 个场景和判分规则。

| 阶段 | 通过场景 | 通过轮次 | 模型调用 | 输入加输出 Token |
| --- | ---: | ---: | ---: | ---: |
| 首轮留出基线 | 6/8 | 10/13 | 56 | 146,165 |
| 仅修正工具语义 | 7/8 | 11/13 | 55 | 138,711 |
| 同时持久化说明结论 | 8/8 | 13/13 | 56 | 141,806 |

最终回归的读超时与写回执丢失两项检查均通过，审批前退款为 0。人工逐轮复核确认，基线标出的 5 处状态和证据错误没有再出现。已提交的争议仍有多余的提交提示，个别回复也会让用户以为聊天能直接代办券退款。最终数据用于验证已知问题修复，覆盖范围与首次留出集相同。 [回归数据和人工复核](evaluation/mixed-holdout-v1-regression.json)

## 复现

```bash
python -m pytest tests/test_mixed_holdout_eval.py -q
python -m evaluation.mixed_holdout_eval --with-model --output work/mixed-holdout/new-run.json
```

第二条命令会使用 DeepSeek API 额度。输出路径需为新文件，以保留先前报告。运行报告同时记录场景、提示和源码摘要。
